Factory Inventory Management System

Architecture overview of the inventory-management demo: a Vue 3 single-page app talking over HTTP to a FastAPI service that serves filtered, Pydantic-validated views of JSON mock data held in memory. No database, no authentication.

Vue 3.4 + Vite 5 FastAPI + Pydantic 2 JSON in-memory data pytest (40 backend tests) Branch: new_features

01System architecture

Two processes in development. The browser loads the SPA from the Vite dev server on port 3000, and the SPA calls the API directly on port 8001 (there is no Vite proxy; the backend allows it with permissive CORS). All data is read from JSON files once, at backend import time.

03Data flow: one filter change, end to end

The same path serves every filtered view. Example: the user picks "Tokyo" in the warehouse filter while on the Orders page.

  1. FilterBar updates shared state components/FilterBar.vue → composables/useFilters.js

    The select is bound to the selectedLocation ref. useFilters is a module-level singleton, so every view sees the same refs.

  2. The active view reacts and refetches views/Orders.vue

    A watch on the filter refs calls getCurrentFilters(), which returns {warehouse, category, status, month}, then calls the API client.

  3. api.js builds the request src/api.js → axios

    Each filter is appended to URLSearchParams only if set and not 'all'. Result: GET http://localhost:8001/api/orders?warehouse=Tokyo.

  4. FastAPI route filters in memory server/main.py: get_orders()

    apply_filters() does exact warehouse match and case-insensitive category/status; filter_by_month() substring-matches order_date and expands Qn-2025 via QUARTER_MAP.

  5. Source list comes from mock_data server/mock_data.py ← data/orders.json

    The orders list was loaded once at import. Nothing is written back; restarting the server resets everything.

  6. Pydantic validates the response response_model=List[Order]

    Each dict is coerced to the Order model and serialized to JSON. Aggregate endpoints (dashboard summary, reports) return plain dicts computed on the fly instead.

  7. View derives display data views/Orders.vue computed properties

    Raw rows land in a ref (allOrders); totals, groupings, and chart points are computed properties. useI18n translates labels and converts USD to JPY for the ja locale.

08Findings worth knowing

Things that are easy to trip over when changing this code.

  • Frontend calls endpoints the backend does not have. api.js defines task CRUD and purchase-order calls, and App.vue requests /api/tasks on every load. The 404 is caught silently and mock tasks from useAuth are shown instead. Purchase-order models exist in main.py with no routes.
  • Reports.vue is an outlier. It uses axios directly with its own hardcoded base URL, ignores the global filters, and is not translated. Any base-URL or filter change has to be made there separately.
  • No Vite proxy. The SPA hits http://localhost:8001 directly, relying on allow_origins=["*"]. Deploying behind one origin would mean adding a proxy or making the base URL configurable.
  • Backlog.vue is unrouted. Backlog data is shown inside the Dashboard; the standalone view is dead code unless a route is added in main.js.
  • Inventory has no time dimension. The month / quarter filter is accepted by the UI but not sent to /api/inventory; only orders and the dashboard summary honor it.
  • State resets on restart. All data lives in Python lists loaded at import. There is no write path today, and adding one would not persist across restarts without further work.
  • Test coverage is backend-only. 40 pytest cases cover inventory, dashboard, demand, backlog, spending, and root. Orders and reports endpoints have no dedicated tests; the frontend has none.
